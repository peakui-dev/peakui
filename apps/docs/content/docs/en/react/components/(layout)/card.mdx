
### Anatomy

```tsx
import {Card} from "@peakui/react";

export default () => (
  <Card>
    <Card.Header>
      <Card.Title>Title</Card.Title>
      <Card.Description>Description</Card.Description>
    </Card.Header>
    <Card.Content>Content</Card.Content>
    <Card.Footer>Footer</Card.Footer>
  </Card>
);
```

## Styling Reference

PeakUI follows the [BEM](https://getbem.com/) methodology, so variants and states are plain class names you can target.

### CSS Classes

The Card component uses these CSS classes ([view source styles](https://github.com/peakui-dev/peakui/blob/main/packages/styles/components/card.css)):

#### Base Class [!toc]

- `.card` - Base card styles: flex column, gap, padding, surface shadow and radius

#### Variant Classes [!toc]

- `.card--default` - `bg-surface`
- `.card--secondary` - `bg-surface-secondary`
- `.card--tertiary` - `bg-surface-tertiary`
- `.card--transparent` - No background, border or shadow

#### Element Classes [!toc]

- `.card__header` - Header region: flex column
- `.card__title` - Title: `h3` text styles
- `.card__description` - Description: `p` text styles
- `.card__content` - Body region: flex column, takes the remaining space
- `.card__footer` - Footer region: flex row, centered

### Slots

- `[data-slot="card"]` - The root element
- `[data-slot="card-header"]` - The header region
- `[data-slot="card-title"]` - The title
- `[data-slot="card-description"]` - The description
- `[data-slot="card-content"]` - The body region
- `[data-slot="card-footer"]` - The footer region

## API Reference

### Card

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `children` | `ReactNode` | - | The card content (required) |
| `variant` | `'default' \| 'secondary' \| 'tertiary' \| 'transparent'` | `'default'` | Surface level the card paints |
| `className` | `string` | - | Additional classes |
| `render` | `DOMRenderFunction<'div', undefined>` | - | Replaces the rendered `<div>` with your own element |

Every other attribute of a `<div>` is accepted.

Every variant except `transparent` provides `SurfaceContext`, so nested controls re-base their fills on the card's level.
