## Global Constraints

Copied from the spec:

- Add `Sheet` to `@peakui/react` on top of `react-aria-components/Sheet` (RAC 1.22.1, branch `chore/bump-rac-1.22`). Status `alpha`.
- `Sheet` sits **alongside** `Drawer`; it does not replace it. Non-goals: replacing or deprecating `Drawer`; a `Drawer`-to-`Sheet` codemod; changes to core primitives; docs-site licence text (deferred by the owner).
- Parts: `Sheet` (root), `.Trigger`, `.Backdrop`, `.Content`, `.Dialog`, `.Header`, `.Heading`, `.Body`, `.Footer`, `.Handle`, `.Close`, `.CloseTrigger`, `.NestedRoot`.
- Root props: `isOpen` / `defaultOpen` / `onOpenChange` (default `false`); `onClose`; `onAnimationEnd: (open: boolean) => void`; `isDismissable` (default `true`); `placement: "bottom" | "top" | "left" | "right"` (default `"bottom"`); `snapPoints: Array<number | string>` (pixels or any CSS length; opens at the first; trailing `1` ignored; default full height); `isDetached` (default `false`).
- `isExiting` is a render prop and `data-exiting` on `Backdrop`, `Content` and `Dialog`. `NestedRoot` is a `Sheet` with `isNested` set internally; it scales the parent back. Every part accepts `className` (string or render function) and `ref`. Types live inline.
- Snap points are normalised to a sorted list; full height is always implicit. Release settles on the nearest point, biased by velocity. A drag past the lowest point dismisses when `isDismissable`.
- Touch on the panel swipes natively through scroll-snap. A pointer drag on `Handle` drives the scroller programmatically and releases on the shared easing curve. Scrolling Body content takes precedence over sheet movement until it reaches its edge.
- Nested: scales and dims the parent; closing the child restores the parent's snap point; Escape closes the topmost sheet only.
- Reduced motion: enter, exit, release and stack-scale transitions become instant; snap points still apply; programmatic scrolls use `behavior: "auto"`.
- RTL: `left` and `right` are physical edges; no `start`/`end`; `placement` does not flip. Handle arrow keys on a horizontal sheet follow the logical direction of the inline axis.
- Forced colors: panel, handle and backdrop get `CanvasText` borders and a `Highlight` focus ring; the backdrop falls back to a stippled `Canvas`.
- `Dialog` is `role="dialog"` with `aria-labelledby` pointing at `Heading`; focus trapped, returns to `Trigger` on close, page behind inert.
- `Handle` is a keyboard-operable `role="slider"`, `aria-orientation` per placement, `aria-valuemin` (lowest snap), `aria-valuemax` (full), `aria-valuenow`, `aria-valuetext` such as "Half height". Arrow keys step to the adjacent snap point, Home and End jump to the extremes. Escape closes. Handle is rendered only when `snapPoints` has more than one entry; otherwise it is decorative (`aria-hidden`).
- `Close` and `Handle` targets are at least 24x24 CSS px; focus is never obscured by the sheet edge (WCAG 2.2 AA, SC 2.5.7).
- Reuse `Surface` and `CloseButton` unchanged; `Drawer` behaviour does not change.
- Pin the RAC range and import through one module. Scroll-snap differs across Safari and Chromium: the e2e matrix must include WebKit.
- Tests: jsdom has no assertions on colours or class lists. Playwright covers scroll-snap settling, handle drag and release, swipe-to-dismiss, nested scale-back, four placements, `isDetached`, emulated reduced motion, RTL, forced colors, keyboard stepping against live `aria-valuenow`.
- Sheet vs Drawer docs text uses no product names.

Project rules every task also obeys (`peakui/AGENTS.md`, `peakui-component-standards`): `"use client"`, no `forwardRef`, `use(Context)`, named exports, `data-slot` after the props spread, `tv()` BEM only, no `any`, documents in English. Stage 5 of the pipeline is switched off: **write no changeset and no codemod.** Never hand-edit the five generated registries; run `pnpm registries`.

## Review Focus

Input classes the spec implies but does not state, most likely first. Each is pinned by a test in the named task.

1. **Garbage `snapPoints`**: `[]`, `[1]`, `["100%"]`, duplicates, unsorted, NaN, negative, unparseable strings. Expect: normalised or dropped, sheet opens at full height, never throws. (Task 2)
2. **Rapid open/close and controlled `isOpen` flipping mid-animation**: expect `onAnimationEnd` once per settled state, no stuck `inert`/`aria-hidden`, focus returned to Trigger. (Task 5)
3. **Unmount while dragging or while open** (route change): expect pointer capture released, rAF cancelled, nothing left inert. (Task 7)
4. **Handle with one snap point, or zero-size layout** (hidden ancestor, jsdom): expect `aria-hidden` decoration or finite `aria-valuenow`; arrow keys at the ends do nothing, never `NaN`. (Task 6)
5. **`isDismissable={false}`** across every path: outside press, Escape, Handle Home/End/drag-past-lowest, swipe. Expect `onOpenChange` never fires with `false`. A non-primary mouse button or second pointer must not start a Handle drag. (Tasks 4 and 7)

## Spec gaps found

1. **Drawer helper does not exist as specified.** "Placement, backdrop, close wiring" is not shared code in `drawer.tsx`; the real shareable pieces are the edge-placement union and the `SurfaceContext` default value (Task 1). `useDrawerDrag` is not reusable. The spec's file list ("shared overlay helper extracted from `drawer.tsx`") was an inference and is corrected here.
2. **`Close` and `CloseTrigger` are inverted** relative to the reference and to `Drawer`: in both, `CloseTrigger` is the `CloseButton` and `Close` clones any child. Plan follows the reference; the spec's wording needs a one-line fix.
3. **Handle contradiction:** "rendered only when snapPoints has more than one entry" versus "otherwise decorative (aria-hidden)". Plan: always rendered; decorative without snap points. Also, `snapPoints=["50%"]` is one entry but two resting positions (the implicit full height): plan makes the slider appear when any partial snap point exists. Open question 1 (button for single-snap) is left open.
4. **`aria-valuemin/now/max` units are unspecified.** Plan uses percent of full extent so "Half height" is derivable.
5. **`isExiting` is an input prop on the reference Backdrop (retention), but a render prop in the spec.** Plan exposes both, as render prop and `data-exiting`.
6. **Reduced motion:** spec says `behavior: "auto"`; the reference uses `"instant"`. Plan follows the spec.
7. **WebKit is required but `playwright.config.ts` has chromium only**; Task 10 adds the project and may need a browser install.
8. **No repo VRT exists** (no `toHaveScreenshot`); the Drawer regression guard is its jsdom suite plus `Drawer.spec.ts`.
9. **Sorting snap points:** the spec says "normalised to a sorted list"; CSS lengths cannot be sorted without layout. Plan keeps author order for RAC (which opens at the first) and sorts measured scroll positions for the handle.
10. **Test-name language:** `testing.md` asks for Russian test names, but the existing `drawer.test.tsx` uses English names. The plan uses English, matching Drawer; flag if the owner wants otherwise.
