# Avatar + AvatarGroup Implementation Plan (roadmap wave 3.1, taken early)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land `Avatar` and `AvatarGroup` in `@peakui/react` and `@peakui/styles` as a reference port
with the full pipeline, so that `peakui-pro`'s `ChatMessage.Avatar` is built on a core component
rather than a local patch.

**Architecture:** One pair, one agent, one branch. `Avatar` composes `@radix-ui/react-avatar` (RAC has
no avatar primitive); `AvatarGroup` is a plain `dom.div` that stacks `Avatar` children and hands them
`size`, `color` and `variant` through a context module that both components import. The pair lands
together because the reference's `Avatar` root imports that context from its `avatar-group` sibling.

**Tech Stack:** React 19, `@radix-ui/react-avatar` 1.2.6, `tailwind-variants`, Tailwind v4, vitest +
jsdom, Storybook, Playwright, Fumadocs.

**Spec:** `peakui-pro/docs/superpowers/specs/2026-10-16-chat-kit-design.md`, section "Core work order
— `Avatar` + `AvatarGroup`" (a sibling clone, read-only for this plan). Its parent here:
`docs/superpowers/specs/2026-10-04-component-roadmap-design.md`, wave 3.1 and "New third-party
dependencies". The consuming plan: `peakui-pro/docs/superpowers/plans/2026-10-16-chat-kit.md`, Task 9.

**Standard:** `AGENTS.md`, the `peakui-component-standards` skill and its `references/`, the
`peakui-docs` skill. **Skills cited by this work:** `superpowers:writing-plans`,
`superpowers:executing-plans`, `peakui-component-standards`, `peakui-docs`, `playwright-e2e`.

## Decisions (where the standard and the reference differ)

The reference is the shape; the core's standard wins wherever they disagree. Each row is a deliberate
difference. Each one that touches a stylesheet is repeated at the end of its `.css`, as `chip.css` does.

| # | Reference | Here | Why |
| --- | --- | --- | --- |
| 1 | Radix is a plain dependency | Same, `1.2.6`. The roadmap spec says `AGENTS.md` names it as a binding choice; `AGENTS.md` does not (it lists RAC and no Radix). The roadmap spec is where the decision is recorded. RAC has no avatar primitive, which is the standard's condition for reaching down. | Reported, not silently settled |
| 2 | No `data-slot` on any Avatar element | `data-slot` `avatar`, `avatar-image`, `avatar-fallback`; group: `avatar-group`, `avatar-group-count`, placed **after** the props spread | Standard: every rendered element, after the spread |
| 3 | `AvatarGroupCount` sets `data-slot` before its spread, then hands it to `Avatar` | The root takes an internal marker prop `AVATAR_SLOT` for the one case where a different part owns the root element; otherwise `avatar` | A root that sets `data-slot` after its spread would otherwise erase the Count's slot |
| 4 | `Avatar.Root`, `.Image`, `.Fallback` inherit Radix's `asChild` | `asChild` is omitted from the Root and Fallback prop types; kept on `Avatar.Image`, where a framework image component is the one real use | Standard: polymorphism by `render`, not `as`; Radix's `Image` cannot take a render function |
| 5 | Every visible child of the group is cloned with the group marker | Host elements (`typeof child.type === "string"`) are not cloned | The marker would reach the DOM as an unknown attribute |
| 6 | `displayName = "HeroUI.AvatarGroup.Count"`; remote CDN images; Iconify icons | No `displayName` (inferred; `isCountElement` compares by identity); stories and demos use inline SVG data-URI images and an inline glyph | Names the reference; offline, deterministic VRT |
| 7 | CSS tokens spelled `var(--background)` | `var(--color-background)`; the md size lives in the base class (already so); a `forced-colors` block | `--color-` prefix, `css-authoring.md`, design-tokens spec |
| 8 | `AvatarImage` destructures nine props and re-passes each | One `...props` spread, then `data-slot` | Same behaviour, less code |

## Review Focus

1. **A group child that is not an `Avatar`.** `<AvatarGroup><span>x</span></AvatarGroup>` logs no React
   warning about an unknown attribute and the span is untouched (Decision 5). Test in Task 2.
2. **An explicit `size` on a child beats the group's.** `<AvatarGroup size="sm"><Avatar size="lg">`
   renders `lg`. Task 2.
3. **An avatar nested inside a group child does not inherit.** Only direct children are marked. Task 2.
4. **`max={0}` and `max` above the child count.** `0` shows no avatars and a `+N` count of all; a `max`
   at or above the count adds no count. Task 2.
5. **Image fails or is absent.** No `src`, or a `src` that errors, shows the fallback; a loaded image
   hides it. Task 1 (jsdom with a stubbed `window.Image`) and Task 4 (a real browser).
6. **Forced colours.** The avatar keeps a visible boundary when backgrounds are flattened. Task 4.
7. **`ChatMessage` consumer contract** (see Task 1 Interfaces): an image with `alt`, a text fallback,
   and a consumer-owned `show`.

```ts
// avatar-group-context.ts
export const AVATAR_GROUP_CHILD = "__avatar_group_child";
export const AVATAR_SLOT = "__avatar_slot";
export interface AvatarGroupContextValue {
  slots?: ReturnType<typeof avatarGroupVariants>;
  size?: AvatarVariants["size"];
  color?: AvatarVariants["color"];
  variant?: AvatarVariants["variant"];
}
export const AvatarGroupContext: Context<AvatarGroupContextValue>; // default {}

// avatar.tsx
interface AvatarRootProps extends Omit<ComponentPropsWithRef<typeof AvatarPrimitive.Root>, "asChild" | "color">, AvatarVariants {
  [AVATAR_GROUP_CHILD]?: boolean;
  [AVATAR_SLOT]?: string;
}
interface AvatarImageProps extends ComponentPropsWithRef<typeof AvatarPrimitive.Image> {}
interface AvatarFallbackProps extends Omit<ComponentPropsWithRef<typeof AvatarPrimitive.Fallback>, "asChild"> {
  color?: AvatarVariants["color"];
}
export const Avatar = Object.assign(AvatarRoot, {Root: AvatarRoot, Image: AvatarImage, Fallback: AvatarFallback});
// avatarVariants: slots base "avatar", fallback "avatar__fallback", image "avatar__image";
//   color accent|danger|default|success|warning (on fallback); size sm|md|lg (on base); variant default|soft;
//   defaults color "default", size "md"
```

- **The consumer contract.** The core `Avatar` is a compound. It has **no** `alt`, `fallback` or `show`
  prop, and the standard forbids an assembled form. `ChatMessage.Avatar` therefore composes
  `<Avatar><Avatar.Image alt src /><Avatar.Fallback>{fallback}</Avatar.Fallback></Avatar>` and owns
  `show` itself. `alt` and `src` reach the `<img>` through `Avatar.Image`; the text fallback is the
  children of `Avatar.Fallback`. This is reported to the controller, not worked around here.
