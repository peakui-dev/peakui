# Accessibility and i18n floor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise every existing component to the accessibility-and-i18n floor: forced-colors-safe selected states, five localized assistive strings, and a jsdom axe check per interactive component.

**Architecture:** Six independent batches (spec "Work slicing") become Tasks 1-6 after a CodeGraph context task. A shared `expectNoAxeViolations` helper lands first; the string dictionary is one module consumed by five leaf components via `useLocalizedStringFormatter`; forced-colors rules are CSS in `@peakui/styles`, with one opt-in shared utility.

**Tech Stack:** React 19, react-aria-components, `@react-aria/i18n`, `axe-core` (jsdom tier), vitest + `@testing-library/react`, Tailwind v4 CSS in `@peakui/styles`, Playwright + `axe-playwright` (Storybook tier).

## Global Constraints

Copied from the spec:

- Raise every existing component to the floor in `.agents/skills/peakui-component-standards/references/accessibility-and-i18n.md` without adding components or changing public API.
- Every selected/checked/filled state stays distinguishable under `forced-colors: active`.
- Every assistive string a component generates is localized (`en-US`, `ru-RU`), and a consumer label still wins.
- An axe check runs in the jsdom tier for every interactive component.
- Non-goals: new components, API changes, locales beyond en and ru, `prefers-reduced-transparency` sweep, Pro and agents repositories, WCAG 3 / APCA gating, slider marks and steps.
- Forced colors: transparent border in normal state, `ButtonBorder` in forced colors, `Highlight`/`HighlightText` for selected, system colors only inside the query. Prefer one shared utility (`status-selected-forced`) in `utilities/index.css` over per-file copies if three or more components need identical rules; keep it opt-in via `@apply`.
- Strings: one shared module `packages/react/src/i18n/strings.ts`, keys `close`, `pagination`, `loading`, `clearSearch`, `removeTag`, locales `en-US` and `ru-RU`; components call `useLocalizedStringFormatter(strings, "@peakui/react")` and keep the existing prop order, so a consumer `aria-label` still wins. Add `@react-aria/i18n` as a dependency.
- Axe helper: `packages/testing/helpers/axe.ts` exporting `expectNoAxeViolations(container, options?)` wrapping `axe-core` with `color-contrast` and `region` disabled; re-exported from `helpers/index.ts`. Each interactive component gets one `it("не имеет нарушений axe")` in its existing `tests/components/<name>/<name>.test.tsx`, rendered with its accessible name supplied.
- No assertions on computed colors (testing standard). Russian text in tests follows the repo convention; Russian in JSX is a defect.
- Hook in five leaf components may break server-component usage; run `require-client-directives`.
- Batches are independent; file lists do not overlap. Batch 2 owns the five string components' tests, so batch 5 excludes them. Batch 3 alone edits `utilities/index.css`.

Repo rules that apply to every task: Conventional Commits (header up to 150 chars), named exports only, kebab-case files, stories stay beside the component, registries are generated (no new component here, so `pnpm registries` is not needed), and stage 5 of the Pipeline is switched off, so **write no changeset**. All commands run from `C:\Users\Vlad\Desktop\projects\io\node\peakui-company\peakui`.

## Review Focus

Five input classes the spec is silent on, most likely first. Each is pinned by a test in the owning task.

1. **Regional or unsupported locale** (`ru`, `de-DE`, an RTL locale such as `ar-EG`): labels fall back to the English string, never an empty name or a thrown missing-key error. Pinned in Task 2.
2. **Consumer naming via `aria-labelledby`** (not only `aria-label`) on spinner, pagination and close button: the consumer name must win over the localized default. Pinned in Task 2.
3. **Hydration under a non-default locale** (`I18nProvider locale="ru-RU"` on server and client): no mismatch from the new hook. Pinned in Task 2 (SSR suites).
4. **Axe helper that passes vacuously**: an unnamed control or a failed run must fail the helper, and open overlays render outside `container`, so the check must be able to target `document.body`. Pinned in Task 1 (helper self-tests) and Task 5 (overlay components).
5. **Compound states in forced colors**: indeterminate, disabled+checked and invalid+checked checkbox/radio/switch, and a selected-and-disabled tab. These are where a single-fill fix silently fails. Pinned in Task 3/4 (a story per state, new stories added with the CSS) and Task 6 (snapshot and axe sweep over them).
